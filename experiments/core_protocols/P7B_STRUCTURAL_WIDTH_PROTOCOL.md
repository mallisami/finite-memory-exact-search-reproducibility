# Paper 2 P7B — Structural Portfolio-Width Characterization Protocol

**Status:** frozen before execution. Exploratory structural-regime characterization; no objective-outcome criterion may be used to select the confirmatory regime.

## Purpose
The P7 pilot showed online reusable state and better learned retention, but the baseline geometry produced at most two simultaneously live valid checkpoints. P7B asks which structural settings naturally instantiate genuine multi-state persistence competition.

## Frozen matrix
- Domains: generic, workflow, microservice.
- Problem scales `(nodes, hosts)`: `(24,6)`, `(32,8)`, `(40,10)`.
- Destroy sizes: `5`, `8`, `12`.
- Fresh seeds per domain: `2626`, `2727`, `2828`.
- Independent structural cases: `3 × 3 × 3 × 3 = 81`.
- Controller iterations/case: `200`.
- Exact-search slice: `8` deterministic branch pops/call.
- Persistence policy: keep all valid unfinished checkpoints.
- Repair-context trace: generated by the ordinary matched controller for the same domain/scale/destroy size; no recurrence sampler and no supplied trace.

## Mechanistic endpoints only
P7B records no objective-improvement comparison for regime selection. Endpoints are:
- peak live valid checkpoint count;
- mean live checkpoint count;
- fraction of iterations with `K_live >= 2`, `>= 3`, and `>= 4`;
- natural exact repair-context recurrence events;
- useful compatible resumes;
- prior branch pops reused;
- checkpoint creation and exact-retirement counts;
- fraction of calls returning unfinished exact search state;
- invalidation evictions;
- checkpoint-size and keep-all peak-byte statistics;
- ratio `max_checkpoint_bytes / keep_all_peak_bytes` as a budget-resolution diagnostic.

## Eligibility for a genuine multi-state confirmatory regime
A structural regime is eligible only if, across its 9 independent cases (3 domains × 3 seeds):
1. median peak live checkpoint count is at least 4;
2. at least 6/9 cases reach `K_live >= 4`;
3. median fraction of iterations with `K_live >= 4` is at least 0.05;
4. median useful compatible resumes is greater than 0;
5. median unfinished-return fraction is at least 0.20;
6. median `max_checkpoint_bytes / peak_bytes <= 0.40`, so one state does not consume most of keep-all capacity.

## Selection rule among eligible regimes
Choose the regime by this fixed lexicographic ranking:
1. highest median fraction of iterations with `K_live >= 4`;
2. highest median peak live checkpoint count;
3. highest median useful resumes;
4. lower structural scale `(nodes, hosts)` if still tied, to minimize confirmatory compute.

**Final objective, anytime objective, learned-policy performance, and restart-vs-persistence advantage are forbidden selection variables.**

## If no regime is eligible
Do not cherry-pick the least-bad case. Report that the current controller/instance families do not naturally instantiate sustained multi-state competition under this grid, and reconsider the practical scope of the Paper-2 claim before running confirmatory P7.
