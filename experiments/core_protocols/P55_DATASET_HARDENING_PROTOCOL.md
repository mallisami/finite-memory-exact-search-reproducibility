# Paper 2 P5.5 — Dataset / Protocol Hardening

## Status
**Frozen pre-ML hardening gate.** P5.5 does not claim ML superiority or end-to-end controller benefit.

## Purpose
P4/P5 established controlled allocation headroom and the distinction between recurrence and legal resumability. The independent audit identified four pre-ML risks: pseudo-replication, synthetic recurrence, future leakage, and insufficient independent cases. P5.5 addresses those risks before any model is fit.

## Natural-controller corpus
P5.5 uses the existing matched outer-LNS controller with its ordinary destroy operators and two heuristic repair arms. It does **not** use `RecurrenceSampler`, supplied repair traces, or curated interaction perturbations.

Per base case:
- domain: generic / workflow / microservice;
- 24 nodes, 6 hosts;
- destroy size: 8;
- 200 deterministic controller iterations;
- controller seed: fixed from the base instance seed;
- decision iterations: 20, 30, ..., 160;
- future prediction horizon: 40 controller iterations.

At each declared decision iteration, the current repair context and placement generate a real unfinished exact PCR checkpoint. Future occurrences of the **same destroy set** are observed from the later unmodified controller trace. Legal reuse is tested using PCR's exact `cache_equal_for_resume` rule.

Thus the main target is:

`future_compatible_recurrence = 1`

iff at least one exact recurrence within the next 40 iterations remains legally resumable.

## Independent cases
Frozen seeds per domain:

101, 202, 303, 404, 505, 606, 707, 808, 909, 1010, 1111, 1212, 1313, 1414, 1515.

This yields 45 independent base cases and 675 decision events (15 per case).

Rows within the same base case are repeated measurements and must never be treated as independent cases.

## Invested-work randomization
Invested branch-work levels are shuffled **within each case using a pre-decision deterministic seed**. This prevents invested work from becoming a deterministic proxy for decision iteration. The frozen corpus has correlation approximately -0.034 between invested work and decision iteration.

## Frozen grouped split
All rows from one `(domain, instance_seed)` remain in the same split.

Per domain:
- train: first 9 frozen seeds;
- validation: next 3;
- test: final 3.

Totals:
- train: 27 cases / 405 rows;
- validation: 9 cases / 135 rows;
- test: 9 cases / 135 rows.

No base case may be moved after model performance is inspected.

## Feature firewall
The canonical firewall is `PAPER2_P55_HARDENED/P55_FEATURE_FIREWALL.json`.

Only explicitly listed decision-time fields are model inputs by default. Future, outcome, oracle, and post-decision fields are forbidden. Experimental labels such as future scenario identity are not predictors.

The default target is `future_compatible_recurrence`.

## Statistical unit
Prediction rows are event-level, but uncertainty and generalization claims must respect the grouped base-case structure. Final confidence intervals / paired controller comparisons should resample or model base cases, not treat 675 rows as independent experimental replicates.

## Relation to P5
P5 remains a controlled stress test with designed compatibility regimes. P5.5 supplies the natural/unselected controller corpus. They answer different questions and must not be silently pooled as if generated by the same process.

## Interpretation boundary
P5.5 establishes an ML-ready **data-generation and evaluation protocol**, not an ML result and not an online budgeted-persistence performance claim. The next gate is baseline-first P6 prediction using the frozen firewall and splits.
